# Plan for #4: Filter runs by vehicle on the web page

## Goal
Add a labelled vehicle filter above the runs table that hides non-matching rows as the user types and restores all rows when cleared.
The filter stays client-side; loading, creating runs, API behavior, and deployment configuration remain unchanged.

## Dependencies (confirmed / plausible / open)
- confirmed, change: yes — `public/index.html`, `load()` and runs table: retain loaded run data and render rows using the current filter.
- confirmed, change: yes — `e2e/smoke.spec.ts`: cover typing `WVW-1001`, visible matching runs, and clearing the input.
- confirmed, change: no — `src/app.ts` and `src/runs.ts`: API already returns the runs needed for client filtering.
- confirmed, change: no — `src/config.ts`, `k8s/`, `README.md`: no configuration or API contract changes.
- plausible, change: no — unit, rollout, stability, smoke, and deploy pipeline behavior should be unaffected; browser job exercises the changed UI.

## Tests
- `e2e/smoke.spec.ts`: type `WVW-1001` and assert only those runs remain; clear and assert all seeded rows return.
- Run `npm run verify` and `npm run e2e` against the local app.

## Environment contract
No environment variables change; `src/config.ts`, `k8s/configmap.yaml`, and the README environment table stay unchanged.

## Risks
- Filtering only the DOM after a rerender could lose the filter state; keep loaded data and filtered rendering together.
- The test must verify row identity/count without depending on parallel test ordering or fixed global row totals.
- Unit, browser, and pipeline test stages can fail; deploy and health checks should be unaffected.

## Open questions
- None.

## Decisions
- Use a client-side case-insensitive substring match on vehicle ID; clearing the input restores all runs.
