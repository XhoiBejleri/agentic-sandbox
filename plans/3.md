# Plan for #3: Add DELETE /api/runs/:id

## Goal
Test engineers can delete an existing non-running measurement run through `DELETE /api/runs/:id` and receive an empty 204 response.
Unknown runs remain unchanged and return 404; running runs remain stored and return 409.

## Dependencies (confirmed / plausible / open)
- confirmed, change: yes — `src/runs.ts`, `RunStore`: add synchronous removal behavior while preserving existing create/list/get semantics.
- confirmed, change: yes — `src/app.ts`, `/api/runs/:id`: add DELETE handling, reuse the documented 404 shape, reject `status === "running"`, and return 204 only after removal.
- confirmed, change: yes — `test/app.test.ts`, runs API tests: cover successful deletion plus follow-up GET/list absence, unknown id, and running conflict/preservation.
- confirmed, change: yes — `README.md`, API table: document the new endpoint and its 404/409 responses.
- confirmed, change: no — `public/index.html` and `e2e/smoke.spec.ts`: no delete UI is requested, so browser behavior is unchanged.
- confirmed, change: no — `src/config.ts` and `k8s/`: no environment or deployment change.
- plausible, change: no — pipeline rollout, stability, smoke, and browser behavior should remain unchanged; verify through CI.
- confirmed, change: yes — the approved 409 body includes both `error` and the run `id`.

## Tests
- `test/app.test.ts`: delete a seeded planned run; expect 204 with no body, then confirm GET returns 404 and list omits it.
- `test/app.test.ts`: delete an unknown id; expect 404 `{ error: "run not found", id }`.
- `test/app.test.ts`: arrange a running run in a dedicated store; expect 409 and confirm the run still exists.
- Run `npm run verify`.

## Environment contract
No environment variable is added or changed; `src/config.ts`, `k8s/configmap.yaml`, and the README environment table stay unchanged.

## Risks
- Returning JSON with 204 would violate HTTP semantics; the response must be empty.
- Removing before checking status could lose a running run.
- A store removal bug could leave list/get inconsistent.
- Unit or pipeline test stages can fail; deploy and browser stages should have no behavioral change.

## Open questions
- None.

## Decisions
- Include the run `id` in the 409 response alongside `error: "run is in progress"`.
